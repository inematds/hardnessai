MÓDULO 1.6 · "MODO ENSEÑANZA"

🪟 Ventana de contexto escasa

La IA tiene una «memoria de trabajo» finita: la context window. Cada cosa que metes ahí dentro (skills, instrucciones, archivos) consume una parte de ella. Aquí aprendes el lema de Matt Pocock: "cada skill cobra" — y cómo mantener el contexto limpio para que la IA piense mejor. Cada palabra nueva se explica en el momento.

📖 Glosario vivo (lee antes — vuelve siempre que lo necesites)

Cómo esta es la ruta de Fundamentos, aquí cada término se explica con lenguaje sencillo. Estos son los términos nuevos de este módulo:

Context window (ventana de contexto) — la «memoria de trabajo» de la IA: todo lo que puede «ver» a la vez (tu solicitud + las instrucciones + los archivos + las descripciones de las skills). Es finita: solo tiene cierta capacidad. Piensa en una mesa — admite una cantidad limitada de roles encima.
Token — la «unidad de texto» que cuenta la IA. Más o menos, un fragmento de palabra (en promedio ~4 letras). La context window se mide en tokens; cada cosa que pones ahí consume tokens.
Description (de skill) — la frase corta al inicio de la skill que dice para qué sirve. El modelo decide si usar la skill basándose en ella; por eso se filtra para el contexto, incluso cuando no se usa la skill.
Filtrar (en este contexto) — ocupar espacio en la ventana de contexto sin que quieras. La descripción de cada skill instalada «se filtra»: se queda ahí ocupando espacio, aunque nunca la uses.
disable model invocation — una clave (true) que activas en una skill para decir "solo YO la invoco, el modelo no". Cuando está activada, la description de esa skill no se filtra más hacia el contexto.
Bloat — «inflación». Llenar la context window con demasiadas cosas (skills, MCP servers, un CLAUDE.md enorme). Cuanto más bloat, menos espacio queda para el razonamiento de la IA.
Servidor MCP — un «enchufe» que le da herramientas adicionales al agente (acceso a una base de datos, a una API…). Es útil, pero cada uno también ocupa espacio en el contexto al describir sus herramientas.
CLAUDE.md / agents.md — el archivo de instrucciones permanentes que le das al agente (reglas del proyecto). Entra en la context window siempre — entonces, cuanto más grande, más cuesta.
1

🫥 Qué se filtra en el contexto

🧠 Imagínalo así: una mesa de trabajo. Todo lo que vayas a hacer hoy tiene que caber encima. Si dejas sobre la mesa un menú de cada restaurante de la ciudad —«para elegir eventualmente dónde almorzar»—, queda poco espacio para el trabajo de verdad. La context window es esa mesa: finita, y cada papel ocupa lugar.

La IA no «lo recuerda todo»: solo puede revisar cierta cantidad de texto a la vez. Ese espacio tiene un nombre: context window (ventana de contexto). Se mide en tokens, y cada cosa que entra en la ventana —tu pedido, el historial de la conversación, los archivos abiertos— consume una parte. El problema es que entra mucha información sin que te des cuenta.

El ejemplo central de Pocock son las skills. Toda skill instalada tiene una description — una frase que dice para qué sirve. Con esa frase, el modelo decide si va a usar la skill. Pero para poder decidir, necesita ver la description todo el tiempo. Es decir: la description se filtra para el contexto, incluso cuando nunca se usa la skill. En palabras de Matt: "cada skill filtra su description en la ventana de contexto." El error común de quien empieza es instalar decenas de skills «porque pueden ser útiles»; cada una ocupa su espacio, esté vacío o no.

Cuantas más cosas se apilan, menos espacio queda en la mesa para el razonamiento de la IA (la caja que brilla).

⚠️ Error común de principiante

Instalar todo lo que parece interesante «por si acaso». Cada skill, cada plugin y cada MCP server añade texto que la IA tiene que cargar siempre, aunque nunca lo uses. El contexto se infla y el razonamiento empeora.

En 1 frase: la context window es finita y cada skill instalada filtra su description dentro de ella — ocupando espacio incluso cuando no se usa.

Profundiza (opcional): ¿por qué las «ventanas grandes» no resuelven el problema?

Los modelos nuevos tienen ventanas enormes (cientos de miles de tokens). Pero más espacio no significa más calidad: cuanto más lleno está el contexto, más se «pierde» la IA entre el ruido y más lento y caro se vuelve cada paso. El objetivo no es llenar la ventana, sino mantener dentro solo lo que importa ahora.

2

💸 El costo de 100 habilidades

🧠 Imagínalo así: una cocina con 100 recetas pegadas en la pared. Antes de preparar cualquier plato, el cocinero tiene que leer el título de las 100 para elegir. Si solo preparas arroz, las otras 99 solo estorban a la vista. Cada receta en la pared exige atención, incluso la que nunca usas.

Pocock da el número que se convierte en una regla práctica: "100 skills = 100 descriptions en el contexto". No es que cada skill sea cara por sí sola: es que el conjunto de descriptions se carga junto con el resto cada vez, para que el modelo sepa qué existe. Ni notas diez skills. Cien skills se convierten en un bloque de texto que el modelo tiene que volver a leer a cada paso solo para decidir qué hacer.

La razón es directa: la description existe para que el modelo poder invocar la skill por sí sola. Si está ahí para que se "elija automáticamente", tiene que estar visible. Súmale MCP servers (cada uno describe sus herramientas), al CLAUDE.md y al historial de la conversación, y la mesa se llena antes incluso de que pidas algo. El error común: tratar "lo instalé" como "es gratis". No lo es: estás pagando con contexto por algo que quizá uses una vez al mes.

Recuperación rápida: ¿por qué «100 skills = 100 descriptions en el contexto»?

En 1 frase: "instalé" no significa "gratis": 100 skills cargan 100 descripciones en la mesa cada vez que la IA piensa.

3

🔒 disable model invocation

🧠 Imagínalo así: en lugar de pegar las 100 recetas en la pared de la cocina, guardas la mayoría en un cajón. Siguen ahí, listas, pero solo aparecen cuando tú abre el cajón y la pide. La pared queda limpia; la vista (el contexto) vuelve a ser tuya.

Hay un interruptor para eso: disable model invocation. Toda skill puede ser de dos tipos. Cuando el modelo puede elegirla por su cuenta, la descripción tiene que quedar visible (se filtra). Cuando activas disable model invocation: true, dices: «esta skill solo yo «invoco». Resultado práctico: la description de esa skill no se filtra más hacia el contexto: desaparece de la pared y va al cajón.

Pocock da el ejemplo de la skill "engineering zoom out": la marca como disable model invocation, así que el modelo nunca la activa por su cuenta; solo él, la persona, la llama cuando quiere. Esto encaja con su filosofía: prefiere procedimientos (que tú invocas) a abilities (que el modelo invoca), porque quiere estar «al volante», no delegar el pensamiento. En sus palabras: "I know my skills, I don't want to delegate my thinking." El error común es lo contrario: dejar todo auto-invocable «para ser astuto» y, con eso, llenar la ventana de descriptions que podrías haber ocultado.

🔬 Ejemplo resuelto: ocultar una skill

Tienes una skill "engineering zoom out" que solo usas cuando quieres salir del detalle y mirar todo el sistema. No quieres que la IA decida usarla por su cuenta. Solución: activar la clave en la parte superior (frontmatter) de la skill.

SKILL.md (frontmatter) 
---
name: engineering-zoom-out
description: Sair do detalhe e revisar a arquitetura do sistema.
disable-model-invocation: true   # so EU invoco — a description NAO vaza
---

# Engineering zoom out
1. Liste os modulos e suas responsabilidades.
2. Aponte acoplamentos e dependencias circulares.
3. Sugira 1 refator que reduz a complexidade do todo.

Resultado: la skill sigue disponible para tú llamar; pero la frase de description dejó de ocupar contexto en cada paso del modelo.

En 1 frase: disable model invocation: true saca la description de la pared y guarda la skill en el cajón: solo tú la invocas y el contexto respira.

4

🎈 Bloat de instrucciones

🧠 Imagínalo así: darle a un empleado nuevo un manual de 300 páginas el primer día, con reglas para todo. Se ahoga en el manual y se olvida de la tarea de hoy. Una tarjeta de 1 página con las 5 reglas importantes funciona mucho mejor.

Las skills no son las únicas culpables. El CLAUDE.md (o agents.md), los Servidores MCP y los plugins también aparecen en la ventana. El bloat es exactamente eso: demasiadas instrucciones apiladas. Pocock lo resume con una frase que sirve como diagnóstico: "todo el mundo llena su context window con demasiadas cosas."

La razón por la que duele: cada token de instrucción es un token menos para razonar y, peor aún, las instrucciones contradictorias o irrelevantes confunden el modelo. Un CLAUDE.md con 50 reglas, de las cuales 45 no se aplican a la tarea actual, es ruido. El error común es «acumular»: cada vez que la IA se equivoca, agregas una regla más. El manual crece, el resultado empeora y nunca eliminas nada. La dirección correcta es la opuesta: recortar hasta que duela y conservar solo lo que demuestre su valor.

✓ Contexto conciso

  • • Solo las skills que realmente usas.
  • • CLAUDE.md breve, con reglas que siempre se aplican.
  • • Ocultar (en un cajón) lo que se usa rara vez.

✗ Contexto inflado

  • • Todo instalado «por si acaso».
  • • Una regla nueva con cada error, sin quitar nunca ninguna.
  • • Servidores MCP activados que ni siquiera usas.

En 1 frase: el bloat es demasiadas instrucciones acumuladas: cada token del manual es un token menos para razonar.

5

♻️ El reinicio radical (avance)

🧠 Imagínalo así: un garaje lleno de cosas acumuladas durante años. La mejor forma de organizarlo no es revisar cada objeto uno por uno: es vaciar todo en el patio y solo traer de vuelta lo que realmente usas. Descubriste que el resto ni siquiera te hacía falta.

La receta más radical de Pocock para reducir el tamaño es el reset de 2 pasos (lo verás completo en la Ruta 5). Paso 1: elimina todo — toda skill, todo plugin, todo MCP server, tu CLAUDE.md, agents.md → vuelve a «cero absoluto» y observa el agente trabajar en este modo básico. Su frase es directa: "everyone bloats up their context window with too much stuff." Mira lo que hace la IA sin nada encima.

Paso 2: vuelve a la capa, despacio — y que sean procedimientos (tú invocas), instaladas de una forma que permite personalizarlas y experimentar. Trae solo lo que extrañar de verdad (p. ej.: el brainstorming de superpowers). La lógica es la del garaje: después del reset, la mayoría de las skills que «creías esenciales» ni siquiera las vuelves a instalar. Es la forma honesta de descubrir qué era bloat. El error común es saltarse el paso 1: sin vaciar primero, nunca sientes cuánto estaba acumulado.

En 1 frase: elimina todo hasta llegar a cero, observa la IA «desnuda» y vuelve a agregar solo lo que realmente eches de menos.

6

🧼 Higiene del contexto

🧠 Imagínalo así: cepillarse los dientes. No es una reforma única, sino un hábito pequeño y constante que evita un problema grande. La higiene del contexto es el mantenimiento semanal que mantiene el escritorio limpio sin tener que recurrir a un reinicio radical cada vez.

Al cerrar el módulo (y la Trilha 1): la regla de oro es "cada skill cobra". Trata la ventana de contexto como un recurso escaso que administras activamente. No se trata solo de vaciarla una vez: es un hábito. Audita lo que se filtra y oculta en un cajón lo que rara vez usas con disable model invocation, recorta el bloat del CLAUDE.md y desactiva los servidores MCP que no uses. Abajo está la lista de verificación de higiene: cópiala y ejecútala cada semana antes de empezar un trabajo pesado:

higiene-de-contexto.txt 
CHECKLIST — context window escasso ("cada skill cobra")
[ ] SKILLS — quantas estao instaladas? Usei cada uma no ultimo mes?
[ ] VAZAMENTO — quais descriptions estao vazando a toa? (some-as)
[ ] GAVETA — as raras estao com `disable model invocation: true`?
[ ] CLAUDE.md — toda regra ainda se aplica? Corte as que nao.
[ ] MCP/PLUGINS — algum ligado que eu nao uso? Desligue.
[ ] RADICAL — se ainda estiver inchado: delete tudo, observe, recame.
Regra: cada item na janela e um item a menos de raciocinio.

Recuperación rápida: ¿cuál es el lema de este módulo sobre la context window?

En 1 frase: la higiene del contexto es el hábito de mantener limpia la ventana: cada skill tiene un costo, así que paga solo por lo que usas.
